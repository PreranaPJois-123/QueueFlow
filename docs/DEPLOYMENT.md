## Blueprint

`render.yaml` defines `queueflow-backend` (Docker), `queueflow-frontend` (static),
`queueflow-db` (Postgres), and `queueflow-redis` (Key Value).

- Static sites have neither `region` nor `plan`.
- The frontend obtains its browser-accessible URL using `fromService` with
  `envVarKey: RENDER_EXTERNAL_URL`; private `host`/`hostport` values are unsuitable.
- `CORS_ORIGINS` must be the actual frontend origin, with no path or trailing slash.
  It is intentionally an explicit input, avoiding a reciprocal dependency between
  frontend and backend. `sync: false` prompts only for a new Blueprint. For an
  existing Blueprint, this value must be updated on the backend service itself.
- The backend rejects wildcard/missing production origins and default JWT secrets.
- `JWT_SECRET_KEY` is generated by Render. Database and Redis URLs are references.
- The frontend rejects a missing API URL at build time. Render builds also reject
  HTTP, localhost and single-label internal hosts. The URL is compiled into Vite's
  output, so changing it requires a frontend rebuild.
- SPA paths rewrite to `/index.html`.
- Container startup runs Alembic then `exec` Uvicorn on `${PORT:-8000}`. The health
  check uses the same port. `/api/health` returns 503 if either dependency is down.
- Exactly one Uvicorn worker/Render instance is supported by the current in-memory
  WebSocket manager. Multi-instance operation requires shared pub/sub first.
- PostgreSQL and Key Value public network access is disabled in the Blueprint.

The YAML passes the official Render JSON Schema locally. This is not equivalent
to Render's account-level Blueprint validation: existing resource names, plan
availability, quotas, references and injected URL values still require a real sync.

## Account provisioning

Public registration only creates customers. No existing user roles were modified.
For authorized staff provisioning, the backend includes a privileged command:

```sh
python -m app.provision_user --email STAFF_EMAIL --name 'Staff Name' --role STAFF
```

The command prompts privately for the password and refuses to overwrite existing
users. It requires trusted access to the production database. Do not put passwords
in command-line arguments, source, tickets or build logs. Free Render web services
have no shell access; provisioning must use another authorized database connection
or an approved paid service. No production staff account has been created yet.

JWT logout removes the browser's token. Existing token copies remain valid until
expiry; no server-side revocation is implemented. Queue WebSockets intentionally
expose public token/queue state (no names, emails or JWTs), matching the existing
public queue API. Browser WebSocket origins are restricted to `CORS_ORIGINS`.

## Budget and production limits

The Blueprint retains free plans from the existing repository, so the repair does
not silently introduce paid resources. Render explicitly describes free services
as unsuitable for production: free Postgres expires after 30 days, web services
sleep after 15 minutes of inactivity, and free Key Value is not persistent. A
paid-plan decision is outstanding before claiming an ongoing production service.
No paid resources have been provisioned. Redis currently stores only rate limits;
queue/ticket records belong in Postgres.
